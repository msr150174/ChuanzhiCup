## 四、Git 提交规范

### 提交信息格式

```
<type>: <一句话说清这次做了什么>

Prompt: docs/prompts/01-解析/P02-核心实现.md
模块: PDF 解析 / 锚点生成
```

**type 取值**：`feat` / `fix` / `refactor` / `docs` / `style` / `test` / `chore`

### 正确示范

```
feat: 实现 PDF 锚点生成器，支持 bbox 与字符区间

Prompt: docs/prompts/01-解析/P02-锚点生成.md
模块: PDF解析 / 锚点
```

### 错误示范

```
❌ update                    （看不出做了什么）
❌ 提交代码                   （无信息）
❌ initial commit            （★ 直接违反赛题规则）
❌ 一次性提交全部功能          （★ 直接判负）
```

### 提交节奏（**关键**）

| 频率 | 说明 |
|---|---|
| 每个功能点完成后提交 | 哪怕只有 20 行 |
| 每次 AI 对话产出了可运行代码 → 提交 | |
| Bug 修复单独提交 | 便于在视频里演示"从坏到好" |
| **每天至少 3–5 次** | 太少会被认为不是真实开发 |

> **宁多勿少。** 评委翻提交历史时，看到 40 个小提交远比看到 4 个大提交可信。

### 配置提交模板

```bash
git config commit.template .gitmessage
```

`.gitmessage` 内容：

```
# <type>: <做了什么>
#
# 详细说明（可选）：
#
#
# Prompt 记录：docs/prompts/xx-xxx/Pxx-xxx.md
# 模块：
# ------------------------------------------------
# type: feat | fix | refactor | docs | style | test | chore
# ⚠️ 禁止提交与 Prompt 记录无关的大块改动
```

## 五、演示视频的分镜脚本（**≥2 分钟 AI 协同必须专门设计**）

总长 5–8 分钟，建议这样切：

| 时间 | 内容 | 备注 |
|---|---|---|
| 0:00–0:40 | **痛点与选题** | 讲清楚解决什么问题 |
| 0:40–3:00 | **功能全流程演示** | 核心功能走一遍 |
| **3:00–5:30** | **★ AI 协同过程复现（2.5 分钟）** | **赛题硬性要求** |
| 5:30–6:30 | 架构说明 | 展示你如何约束 AI 的产出结构 |
| 6:30–7:00 | 复现性验证 | 现场从零 clone、10 分钟内跑起来 |

### AI 协同过程这一段怎么拍（**最重要**）

**不要**只是快进播放录屏。要**分屏 + 讲解**：

```
┌─────────────────────┬─────────────────────┐
│  AI 对话窗口          │  代码编辑器          │
│  （展示 Prompt）      │  （展示代码变化）    │
└─────────────────────┴─────────────────────┘
        旁白："这里我只说了需求，
        AI 给出的实现用了 X 方案，
        但我发现它会导致 Y 问题……"
```

**三个必讲的场景**（对应赛题要求的"Prompt 提问 / AI 建议 / 引导修 Bug"）：

1. **一次成功的需求实现** —— 展示 Prompt 如何精准表达意图
2. **一次 AI 给错方案** —— 展示你如何识别并纠正
3. **一次顽固 Bug 的引导修复** —— 展示多轮迭代

> 💡 **第 2 个场景最值钱**。大部分参赛者只展示 AI 多厉害，
> 你敢展示"AI 犯了错，我怎么发现的"——这才是"驾驭能力"。

## 六、README 的"10 分钟极速复现指南"

必须能被评委**掐表验证**。模板：

```markdown
## 快速开始（10 分钟内跑起来）

### 前置要求
- Node.js 18+ / Python 3.11+
- Docker（可选）

### 步骤

1. 克隆（约 1 分钟）
   ```bash
   git clone <你的仓库>
   cd <项目>

2. 配置环境变量（约 2 分钟）
   ```bash
   cp .env.example .env

   ```

   ```bash
   pnpm install && pip install -r requirements.txt
   ```

   docker compose up -d
   ```

5. 访问
   http://localhost:8080

### 常见问题

```

**自测要求**：找一台**从没跑过这个项目的电脑**，掐表走一遍。超时 10 分钟就精简。

## 八、紧急补救（已经来不及的话）

如果前期没留痕，现在补救的办法：

| 情况 | 补救 |
|---|---|
| 早期提交是"测试1~测试6" | **如实说明**：在技术文档写"前期为技术调研期，自 X 日起进入正式开发并建立留痕规范"。**不要删历史，不要 force push。** |
| 没有 Prompt 记录 | 现在开始对**剩下要做的功能**做完整记录；同时把**已有的重要对话**从工具里翻出来（多数工具能查到历史会话） |
| 时间只够做 1 个模块 | 就把那 1 个模块的 Prompt 链做到**极致详细**——3 条链可以来自同一模块的不同迭代 |

> **诚实 > 完美。** 评委见过大量"历史很漂亮但内容空洞"的提交，一段坦率的说明反而更可信。
