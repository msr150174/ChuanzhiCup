## 二、路线 A：直接编译 H5（最快，1 小时）

### 操作

```bash
cd 转换-uniapp前端/guardian-uniapp
npm install
npm run build:h5
# 产物在 dist/build/h5
```

然后部署到 Nginx 或 Vercel。

### 优点
- **零代码改造**
- 立刻有个可访问的 Web 版

### 致命缺点
- **移动端布局在 PC 上呈现为窄条**（uni-app H5 默认按移动端 viewport）
- 评委在电脑上打开会看到"手机模拟器"效果，**用户体验 10% 直接崩**
- 没有桌面端导航、没有多栏布局

### 可用性判断
**只能作为"有个链接"的兜底，不建议作为赛道一正式作品。**

## 三、路线 B：H5 + 响应式适配（1 天，勉强可行）

### 改造点

| # | 改造 | 工作量 |
|---|---|---|
| 1 | 设置最大宽度 + 居中（模拟手机在桌面上） | 0.5h |
| 2 | 桌面端加侧边导航（替换 tabBar） | 2h |
| 3 | 首页改成两栏/三栏布局 | 3h |
| 4 | 表格类页面（告警历史、监测历史）改为桌面表格 | 2h |
| 5 | 字体、间距适配大屏 | 1h |

### 实现示意

```vue
<!-- App.vue 加一个桌面容器 -->
<template>
  <div class="app-shell">
    <aside v-if="isDesktop" class="desktop-nav">
      <!-- 侧边导航 -->
    </aside>
    <main class="app-main">
      <router-view />
    </main>
  </div>
</template>

<script setup>
import { computed } from 'vue'
const isDesktop = computed(() => window.innerWidth >= 1024)
</script>

<style>
.app-shell { display: flex; min-height: 100vh; }
.app-main {
  flex: 1;
  max-width: 480px;        /* 移动端页面在大屏上居中 */
  margin: 0 auto;
  background: #F6F7F9;
}
@media (min-width: 1024px) {
  .app-main { max-width: none; }
}
</style>
```

### 代价
- 只解决"能看"，不解决"好用"
- 用户体验 10% 仍需技巧性包装（强调这是"老年用户移动端为主，Web 为家属端"）

## 六、如果决定做赛道一：技术文档框架

> 赛道一要求 PDF ≤30 页，七章结构。

### 第 1 章 项目概述（2 页）

- 聚焦"**AI Native Web 应用**"，而非"小程序移植"
- 强调：AI 是核心，不是附属
- 建议定位：**"面向家属与机构的 AI 远程守护工作台"**

### 第 2 章 需求分析（2 页）

- 目标用户：家属、社区工作人员
- 核心痛点：远程无法感知长辈状态
- 需求拆解：数据看板、告警处理、AI 健康分析

### 第 3 章 系统架构设计（5 页）

- 前端：Vue 3 + TypeScript + Element Plus
- 状态管理：Pinia
- AI 集成：Vercel AI SDK / 原生 SSE 流式
- 后端：Spring Boot（**说明是 AI 能力接入层**）

### 第 4 章 AI 技术方案（8 页，**权重最高**）

对照赛道一的 AI 技术深度 35% 细分：

| 考察点 | 分值 | 你们怎么写 |
|---|---|---|
| 大模型集成质量（Prompt 设计） | 8% | 展示 AI 对话的 System Prompt 设计 |
| **Agent / 工作流设计** | **8%** | ⚠️ **需补**：把健康分析包装成 Agent 工作流（计划→工具调用→结果） |
| RAG 技术应用 | 6% | ⚠️ **需补**：健康知识库 + 检索增强 |
| 多模态能力 | 5% | ✅ 语音/图像/文本已有 |
| AI 安全与可控性 | 4% | ✅ 三层降级 + 规则兜底 |
| MCP / Function Calling | 4% | ⚠️ **需补**：把 153 个接口封装成工具供 LLM 调用 |

> ⚠️ **关键提醒**：赛道一明确考察 **Agent 工作流（8%）、RAG（6%）、Function Calling（4%）**，合计 **18%**。
> 你们现在**三项都缺**。如果报赛道一，这三项必须补，否则直接丢 18%。

> 而赛道二的评分里**没有单独要求 RAG / Function Calling**——这也是赛道二更适合你们的原因之一。
