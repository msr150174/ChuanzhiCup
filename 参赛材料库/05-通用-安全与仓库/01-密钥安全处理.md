## 一、已完成的代码层脱敏

### 1. `转换-Java后端/guardian-server/.env.example`

**原状态**：文件名叫"example"，内容却是**真实可用的密钥**。

| 变量 | 原值 | 现状态 |
|---|---|---|
| `COZE_API_TOKEN` | `pat_Mlvk...`（真实） | 空 |
| `WX_APP_SECRET` | `65310f...`（真实） | 空 |
| `JWT_SECRET` | `27dcff...`（真实） | 空 |
| `TENCENT_MAP_KEY` | `LQBBZ-...`（真实） | 空 |
| `MYSQL_PASSWORD` | `msr150174`（真实） | 空 |
| `COZE_BOT_ID` | 真实 ID | 空 |

**现状态**：全部为空占位符，并附**填写说明**（告诉使用者去哪里获取）。

### 2. `src/main/resources/application.yml`

**原状态**：三处真实密钥作为**默认值**硬编码，即使不配环境变量也会生效。

```yaml
# 修改前
password: ${MYSQL_PASSWORD:msr150174}
app-secret: ${WX_APP_SECRET:65310f1244e78ae9ded6265bc328b2e6}
key: ${TENCENT_MAP_KEY:LQBBZ-IVMYZ-2VPXD-ZY4BB-EL3JE-CCBN6}

# 修改后
password: ${MYSQL_PASSWORD:}
app-secret: ${WX_APP_SECRET:}
key: ${TENCENT_MAP_KEY:}
```

> **这是最容易遗漏的一类泄露**——很多人只记得改 `.env`，忘了 `application.yml` 里的默认值。

### 3. `set-shared-keys.bat`

**原状态**：批量设置环境变量的脚本里，5 个密钥明文写着。

**现状态**：值为 `""` 空，Token 改为 `PUT_YOUR_NEW_TOKEN_HERE`（脚本有检测该占位符并报错的逻辑）。

## 二、⚠️ 你仍需手动做的事（**我无法代办**）

### 🔴 必做 1：吊销并重新生成所有曾泄露的密钥

代码清理只能防止**未来**泄露。**已经分发出去的历史密钥仍然有效，必须吊销。**

依据 `docs/安全审计报告.md` 的记录，需要轮换：

| # | 密钥 | 平台 | 操作 |
|---|---|---|---|
| 1 | **Coze API Token × 3** | https://www.coze.cn | 个人设置 → API Token → 删除旧的 → 生成新的 |
| 2 | **高德地图 Key × 2** | https://console.amap.com | Key 管理 → 删除 → 新建 |
| 3 | **微信 AppSecret** | https://mp.weixin.qq.com | 开发管理 → 开发设置 → **重置** |
| 4 | **JWT_SECRET** | 本地生成 | `python -c "import secrets; print(secrets.token_hex(32))"` |
| 5 | **腾讯位置服务 Key** | https://lbs.qq.com/dev/console/key/manage | 删除 → 新建 |
| 6 | **MySQL 密码** | 本地 MySQL | `ALTER USER 'root'@'localhost' IDENTIFIED BY '新密码';` |

> 💡 **优先处理 Coze Token**：`pat_` 开头的 Token 权限很大，可调用你账号下所有 Bot，
> 泄露会导致**他人消耗你的额度**。

### 🔴 必做 2：检查旧构建产物

`dist/` 目录下的 `pages/ai-chat/index.js` 仍含**编译进前端包的 Token**。

**虽然没有 `dist/` 就不会被提交**，但如果：
- 你曾上传过小程序体验版/正式版
- 或把 `dist/` 发给过别人

那么这个 Token 仍然有效。**吊销它，重新生成。**

### 🔴 必做 3：新建 `.env` 并填真实值

```bash
cd 转换-Java后端/guardian-server
cp .env.example .env
# 编辑 .env，逐项填入新生成的密钥
```

确认 `.env` 已被忽略：

```bash
git check-ignore -v .env
# 应输出：.gitignore:8:.env	.env
```

### 🟡 建议 4：提交前跑一次密钥扫描

```bash
# 在项目根目录
git log -p | grep -iE "pat_[A-Za-z0-9]{20,}|secret\s*=\s*[0-9a-f]{20,}|password\s*=\s*\S{6,}"
```

或者用 `gitleaks`：

```bash
gitleaks detect --source . --verbose
```

## 三、修改后的正确启动方式

因为 `application.yml` 的默认值已清空，**必须提供环境变量**才能启动。

### 方式 A：使用 `.env` 文件（推荐）

```bash
cd 转换-Java后端/guardian-server
cp .env.example .env
# 填入真实值
```

需确认 `start.bat` 会加载 `.env`。若不会，看方式 B。

### 方式 B：设置系统环境变量

```powershell
$env:COZE_API_TOKEN = "你的新Token"
$env:MYSQL_PASSWORD = "你的数据库密码"
$env:JWT_SECRET = "新生成的随机串"
# ... 其余同理

# 然后启动
.\start.bat
```

### 方式 C：改成必填校验（生产推荐）

在 `application.yml` 中使用无默认值的形式，缺失即启动失败——比静默用默认值更安全：

```yaml
app-secret: ${WX_APP_SECRET}
```

> 注意：这会改变启动行为，**演示前务必测一次能正常起来**。
