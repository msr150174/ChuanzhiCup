## 二、结论：链接在别人电脑上会挂掉的真正原因

**`sharecode` 只存在于首页那一次请求里，进入应用后 URL 就丢了。**

网关（`Server: CloudStudio Gateway`）对**所有不带 `sharecode` 的文档请求**一律返回 403 页面「链接不完整」：

| 请求 | 不带 sharecode | 带 `?sharecode=VSCWG36C44` |
| --- | --- | --- |
| `/` | 403 HTML | 200 HTML |
| `/assets/index-*.js` | 403 | 200 |
| `/api/health` | 403 HTML | 200 JSON |
| `/api/kb/overview` | 403 HTML | 200 JSON（**无 token 也能读**） |

而应用内部跳转的地址形如 `#/page/chat-workspace`，**没有 `?sharecode`**：

```
首次进入:  /?sharecode=VSCWG36C44#/login?redirect=/        ← 参数还在，能开
点一次内部页面: /?sharecode=VSCWG36C44#/page/chat-workspace  ← 同文档内跳转，参数侥幸还在
刷新 / 粘贴 / 点外链: /#/page/chat-workspace               ← 参数没了 → 403
```

`/#/page/chat-workspace?sharecode=xxx` 这种写法更糟：参数在 `#` 之后，**服务器根本收不到**。

你那边看起来正常，是因为本机浏览器里还留着 `__wb_rsc` Cookie（`Max-Age=2592000`，30 天，`HttpOnly; Secure; SameSite=None`）；换台干净电脑就没有了。

## 四、截图里/采集时发现的具体问题

### 1. 严重：登录态与链接参数不是一回事
- 账号密码由**本机服务**校验（登录页原文：「账号密码由本机服务校验，登录态 7 天有效」）。
- `sharecode` 只是网关的准入参数，**不是身份**。评委即使拿到链接，仍需要一个测试账号；而公开注册接口 `/api/auth/register` 带 sharecode 就能直接注册成功（我建了 `dsh_probe_9x7` 做验证，**请记得删除**）。

### 2. 严重：新账号能看到全部历史会话
登录后「对话」页左侧列出的是 `/api/sessions` 返回的 **30 条会话**，标题形如「我是计算机应用技术的大一学生，现在最……」，时间是 11-13 到 11-17。这些不是 `dsh_probe_9x7` 产生的。原因很可能是后端 `student_id` 恒为 `local`（`/api/profile` 返回 `"student_id": "local"`）。

### 3. 严重：知识库原文无鉴权可读
- 页面直接渲染原文（`page-knowledge-base.png` 右侧即《路书·职业规划知识库 v1.1》正文）。
- 接口层面：带 sharecode、**不带任何 token**，`/api/kb/overview`（7059 字节）、`/api/profile`、`/api/sessions` 全部 200。
- 知识库含学校事实、学生手册、专业培养方案等材料，公开发布前需要收口。

### 4. 中：教师侧入口对学生可见
`page-kb-manager.png` 与 `page-kb-upload.png` 都是在**学生账号**下打开成功且可见的。「知识库总览」「上传知识库」属于教师/管理侧，学生侧应隐藏或加权限守卫。

### 5. 中：中文双编码乱码（构建期问题，不是浏览器问题）
`index.html` 的 `<title>` 是真的 `路书工作台 · 智能体工作台`，但部分懒加载产物里是乱码：

```
src 实际字节: 登录失败    →  dist: "鐧诲綍澶辫触"
src 实际字节: 连不上后端服务 →  dist: "杩炰笉涓婂悗绔湇鍔"
```

典型 UTF-8 被当 GBK 解码的二次编码。首页登录框下方的提示「账号密码由本机服务校验」是正常的，说明只有部分 chunk 坏了 —— 大概率是构建机上某些源文件被以 GBK 读入。`index-CEOnjNpj.css` 里 `font-family:Microsoft YaHei,寰蒋闆呴粦` 同理。

### 6. 中：手机端布局
见 `06-mobile-home.png`：390px 宽下左栏品牌区占掉约 45% 宽度，中文被迫逐字换行（「面向高职学 生的智能职业 规划工作台」），「教师 / 管理员」标签也换行。评委很可能用手机点链接。

### 7. 低：页面底部空白条
1440×900 下登录页底部有一条纯白带（`#app` 未铺满视口高度）。不是致命问题，但观感差。

### 8. 低：第三方统计 + 自刷新
页面内嵌百度统计（`hm.baidu.com/hm.js?42f2469b4aa27c3f8978f634c0c19d24` → 实测会拉 `UrlChangeTracker.js` 和 `hm.gif`），另有一段 `window.fetch('?t='+Date.now())` 比对构建时间戳、不一致就 `top.location.reload(true)` 的逻辑。注意：**这段 fetch 本身也走 `?` 参数**，如果它没带 sharecode，理论上会 403 —— 实测本机未被触发，但它在别的网络环境下可能造成不必要的重载。

## 五、建议修复顺序

1. **先解决 sharecode 生命周期**（这是「别人打不开」的根因）：
   - 方案 A（推荐）：首跳校验通过后，由服务端下发一个同源 Cookie（网关已在下发 `__wb_rsc`），后续请求凭 Cookie 放行，不再依赖 URL 参数；
   - 方案 B：前端在 `router.afterEach` 里把所有内部跳转都补上 `?sharecode=`，并在 `index.html` 里先行缓存 `location.search` 供懒加载拼接；
   - 两者都要覆盖：刷新、粘贴、新标签页、手机端。
2. **重新发布并给评委一份"测试流程卡"**：链接 + 测试账号 + 必点页面顺序 + 预计耗时，不要指望评委自己注册。
3. 关闭公开注册；`/api/kb/*`、`/api/profile`、`/api/sessions` 前加鉴权；`student_id` 改为真实账号。
4. 学生侧隐藏「知识库总览 / 上传知识库」。
5. 用纯净 UTF-8 重新构建，修掉双编码乱码与 CSS 里的中文。
6. 补手机端样式（或明确「请用电脑打开」）；修掉底部空白。
