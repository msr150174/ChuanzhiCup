## 二、泄露原因分析

### 根本原因：密钥放在了前端

```
❌ 错误做法（本项目）
   小程序 ──(带 Token)──> Coze API
                ↑
          Token 编译进包里，可被提取

✅ 正确做法
   小程序 ──> 自己的后端 ──(带 Token)──> Coze API
              （无密钥）    （密钥存环境变量）
```

### 为什么前端不能放密钥

| 事实 | 说明 |
|---|---|
| **小程序包可下载** | `.wxapkg` 文件可被抓包获取 |
| **可反编译** | 有成熟工具能还原 JS 代码 |
| **前端代码全公开** | 任何"加密"都只是障眼法 |
| **Token 无法隐藏** | 只要用过一次，就在代码里 |

**这是原理性限制，不是实现问题。**

## 三、修复方案

### 阶段 1：立即止血（今天）

```
□ 吊销 3 个 Coze Token
□ 吊销 2 个高德 Key（或加域名白名单）
□ 检查腾讯地图 Key 的 AppID 限制
□ 查看 Coze 用量账单，确认有无异常调用
```

### 阶段 2：架构调整（1-2 天）

**改造为「后端中转」架构**：

```java
// Java 后端：CozeService.java
@Value("${coze.api-token}")     // ★ 从环境变量读，不进代码库
private String apiToken;

public String chat(String message, String userId) {
    // 用服务端 Token 调 Coze
    // 前端拿不到 Token
}
```

```yaml
# application.yml —— 不放真实值
coze:
  api-token: ${COZE_API_TOKEN:}    # 从环境变量注入
```

```bash
# .env（.gitignore 排除，不进版本库）
COZE_API_TOKEN=pat_新生成的Token
```

### 阶段 3：防复发（长期）

| 措施 | 说明 |
|---|---|
| **密钥进 `.gitignore`** | 确保 `.env` 不被提交 |
| **提供 `.env.example`** | 只给模板，真实值留空 |
| **提交前扫描** | 用 `gitleaks` 等工具自动检测 |
| **最小权限** | Token 只给必需权限 |
| **定期轮换** | 每 3 个月换一次密钥 |
| **用量告警** | 在云平台设置消费告警 |
