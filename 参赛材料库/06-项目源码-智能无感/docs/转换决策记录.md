## 三、原项目的真实业务规则（要保留）

### 睡眠时长评分（4 档）

```java
if (h >= 7 && h <= 9) return min(95 + (h - 7) * 2, 100);  // 最优
if (h >= 6 && h < 7)  return 70 + (h - 6) * 20;            // 一般
if (h > 9)            return 80;                           // 过长
return max(50, h * 10);                                    // 不足
```

### 健康报告评分

```
指标状态映射：good=100 / warning=70 / danger=40
分类得分 = 该分类下指标取平均
综合得分 = 各分类取平均
睡眠效率 = min(100, round(小时数 / 8 * 100))
起床偏差 = round(sqrt(方差))    // 用标准差衡量波动
```

```

else       → evening   (睡前)
```

## 九、实测中发现的真实问题（已修）

### ① AI 规则库「泛词抢先命中」

**现象**：问「我今天睡眠怎么样」，返回的是**健康**建议而不是睡眠建议。

**根因**：规则 2 的关键词里有 `怎么样` 这个泛词，而它在规则列表里排在睡眠规则**前面**，
所以 `我今天睡眠怎么样` 先命中了规则 2。

**修复**：把规则 2 的关键词收窄为 `健康/身体/体质/健康评分/健康分`，去掉 `怎么样`、`状态`。

**教训**：规则库的关键词**越具体越好**，泛词会导致误命中。

### ② 脏缓存会「固化」错误结果

**现象**：第一次 HTTP 测试时中文被 PowerShell 编码破坏，AI 返回了默认回复。
之后**再发正确的中文，仍然返回那个默认回复**。

**根因**：缓存 key 用消息 hash，第一次的坏结果被写进 Redis，
后续相同消息直接命中缓存（TTL 5 分钟），**根本没走到规则匹配**。

**影响**：如果编码在入口就被破坏，坏结果会被缓存并持续返回。

**缓解**：
- 缓存 TTL 保持较短（5 分钟）
- 调试时先 `redis-cli del guardian:ai:cache:*`
- **测试中文接口必须用 UTF-8 编码的请求体**（不要用 PowerShell 内联 JSON）

### ③ javac 中文输出导致「假通过」

**现象**：用 `grep "error:"` 判断 javac 结果，**永远匹配不到**。

**根因**：本机 javac 输出中文 —— `错误: 非法字符`，不是 `error:`。

**后果**：如果有人（或 AI）用 `grep error:` 判断编译结果，会得到**假通过**。

**正确做法**：判断 **退出码**（`$LASTEXITCODE -eq 0`），不要 grep 输出文本。

### ④ PowerShell `Set-Content -Encoding UTF8` 会加 BOM

**现象**：写出的 Java 文件编译报 `非法字符: '\ufeff'`。

**根因**：Windows PowerShell 5.1 的 `-Encoding UTF8` 会加 **BOM**。

**正确做法**：用 `[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))`。
