# 1. ai-chat — 智能助手（AI 对话）

## 1. 页面角色

一个「豆包风格」的 AI 健康助手对话页，用户可用文字或语音与 AI 助手「小护」对话，AI 结合用户本地健康数据（步数 / 睡眠 / 健康评分）给出健康建议。

- 源文件：`ai-chat/index.tsx`（1029 行）、`ai-chat/index.css`（1181 行）
- 页面配置：`navigationBarTitleText: '智能助手'`

## 3. 交互行为

| 操作 | 行为 |
|------|------|
| 点击快捷问题（首屏） | `handleQuickQuestion(q)` → `sendMessage(q)` |
| 点击弹窗内快捷问题 | 先 `closeInputModal()`，再 `sendMessage(q)` |
| 点击输入框 或 键盘按钮 | `openInputModal()`：`showInputModal=true`，清空 `inputText` 与 `inputRef.current` |
| 在弹窗中输入 | `handleInputChange`：同时更新 `inputText` 状态与 `inputRef.current`（ref 用于提交时取最新值） |
| 点击「发送」 | `submitInput()`：`inputRef.current.trim()` 非空才调用 `sendMessage`（**注意：弹窗不会自动关闭**） |
| 点击「取消」/ 关闭图标 / 遮罩 | `closeInputModal()` |
| 点击语音按钮（未录音） | `startRecording()`：① 非小程序环境 → toast「语音功能仅在小程序中可用」；② `checkVoiceprintAgreed()` 为假 → 记录 `pendingVoiceAction='input'` 并弹出声纹授权弹窗；③ `Taro.getSetting()` 检查 `scope.record`：为 `false` → `showModal`「录音权限未开启」+「去设置」→ `Taro.openSetting()`；为 `undefined` → `Taro.authorize({scope:'scope.record'})`，失败则同样引导去设置；④ 权限通过后调用 `recorderManager.start({format:'wav', sampleRate:16000, numberOfChannels:1, encodeBitRate:48000})`、`isRecording=true`、toast「正在录音...」（5s） |
| 点击语音按钮（录音中） | `stopRecording()`：播放成功音效、`recorderManager.stop()`、`Taro.hideToast()` |
| 录音结束回调 `onStop` | `isRecording=false`；若有 `tempFilePath` → `handleVoiceInput()`，当前实现为 toast「语音功能需要后端服务支持，请使用文字输入」并自动打开输入弹窗（ASR 未接入） |
| 录音出错 `onError` | `isRecording=false`，toast「录音失败」 |
| 点击顶部播报开关 | `setAutoSpeak(!autoSpeak)`；开启后 AI 回复打字完成时自动调用 `speakMessage`（当前 TTS 未接入，仅 toast） |
| 点击顶部清空按钮 | `clearMessages()`：`showModal`「确认清空 / 确定要清空所有对话记录吗？」→ 确认后消息重置为单条「对话已清空。有什么新话题想聊吗？😊」，`conversationId=null`，`showQuickQuestions=true` |
| 点击 AI 气泡的复制按钮 | `copyMessage(content, id)`：`Taro.setClipboardData` → `copiedMessageId=id` → toast「已复制」(1.5s)，2 秒后重置图标 |
| 点击 AI 气泡的播报按钮 | `isPlayingAudio` 为假 → `speakMessage()`（toast 提示需后端）；为真 → `stopSpeaking()`：`audioRef.current.stop()`，`isPlayingAudio=false` |
| 点击声纹弹窗「同意」 | 关闭弹窗；若 `pendingVoiceAction === 'input'` → `startRecordingAfterAuth()`：播放提示音 + toast「正在录音...」（loading, 60s）+ `recorderManager.start({duration:60000, sampleRate:16000, numberOfChannels:1, encodeBitRate:48000, format:'wav'})` + `isRecording=true` |
| 关闭声纹弹窗 | `showVoiceprintDialog=false`、`pendingVoiceAction=null`，toast「需要声纹授权才能使用语音功能」 |
| 发送消息流程 | 见下方「业务规则 → 消息发送链路」 |
| 进入页面 | `useEffect` 加载健康数据 + 初始化录音管理器与音频播放器 |
| 消息变化 | `useEffect` 设 `scrollViewId = \`msg-${messages.length}\`` 触发自动滚到底部 |
| 离开页面 | 清理：`stopTypingEffect()` + `audioRef.current.destroy()` |

## 6. 业务规则

### 6.1 消息发送链路（三级降级）

```
sendMessage(text)
  ├─ 前置：text.trim() 为空 或 isLoading 为真 → 直接 return
  ├─ SoundService.play('click')；setShowQuickQuestions(false)
  ├─ 立即把 userMessage 追加到 messages（乐观更新），setIsLoading(true)
  ├─ 方案 1：POST /api/ai/chat  { message, conversationId? }  timeout 60000
  │    └─ 若 respData.data.content 存在：
  │         ├─ 若有 data.conversationId → setConversationId
  │         ├─ 追加 aiMessage，调用 startTypingEffect(aiContent, aiMessage.id)
  │         └─ return（结束）
  │    └─ 抛错或 content 不存在 → 进入方案 2
  ├─ 方案 2：直连 Coze API（硬编码配置）
  │    ├─ COZE_CONFIG = {
  │    │     botId: '7644841783033528370',
  │    │     token: 'pat_***REDACTED***',
  │    │     baseUrl: 'https://api.coze.cn',
  │    │     userId: 'user_001'
  │    │   }
  │    ├─ ① POST {baseUrl}/v3/chat  timeout 30000
  │    │     body: { bot_id, user_id, stream:false, auto_save_history:true,
  │    │             additional_messages:[{ role:'user', content:text, content_type:'text' }] }
  │    │     取 data.data.id → chatId，data.data.conversation_id → convId
  │    │     若缺失 → throw new Error('创建对话失败')
  │    ├─ ② 轮询最多 5 次（maxAttempts = 5），每次间隔 3000ms：
  │    │     GET {baseUrl}/v3/chat/message/list?chat_id={chatId}&conversation_id={convId}
  │    │     在 data.data 中查找 m.type === 'answer' && m.role === 'assistant' 的消息
  │    │     找到即 break
  │    ├─ 若 5 次后仍无内容 → throw new Error(`AI回复为空，已尝试${maxAttempts}次`)
  │    └─ setConversationId(convId)、追加 aiMessage、startTypingEffect
  └─ catch：追加错误消息
       content: '抱歉，小护遇到了一些问题 😔\n请稍后再试，或者换个方式问我~'
  └─ finally：setIsLoading(false)
```

### 6.2 打字机效果

```
startTypingEffect(fullContent, messageId):
  stopTypingEffect()           // 清除上一个定时器
  setIsTyping(true)
  speed = 30                   // 每字符 30ms
  currentIndex = 0
  递归 typeNextChar():
    if currentIndex < fullContent.length:
      displayedContent = fullContent.slice(0, currentIndex + 1)
      更新该消息: { displayedContent, isTyping: true,
                   segments: parseMessageContent(displayedContent) }
      currentIndex++
      typingTimeoutRef = setTimeout(typeNextChar, speed)
    else:
      setIsTyping(false)
      更新该消息: { isTyping: false, displayedContent: fullContent,
                   segments: parseMessageContent(fullContent) }
      SoundService.playSuccess()
      if (autoSpeak) speakMessage(fullContent)
```

### 6.3 消息内容解析（伪 Markdown 规则）

```
parseMessageContent(content):
  segments = []
  for line of content.split('\n'):
    if (!line.trim()) continue                          // 跳过空行
    if (line.startsWith('## ')) → heading level 2, 内容 = line.replace('## ', '')
    else if (line.startsWith('# ')) → heading level 1, 内容 = line.replace('# ', '')
    else if (line.startsWith('- ') || line.startsWith('* '))
         → list, 内容 = line.replace(/^[-*] /, '')
    else if (/^\d+\.\s/.test(line))
         → list, 内容 = line.replace(/^\d+\.\s/, '')
    else → text
  return segments.length > 0 ? segments : [{ type:'text', content }]
```

- 声纹授权后录音：`{ duration: 60000, sampleRate: 16000, numberOfChannels: 1, encodeBitRate: 48000, format: 'wav' }`

## 6. 业务规则

### 6.1 登录态判定

```
if (getStorageSync('guestMode')) → 游客：userInfo = { name:'游客用户', healthLevel:'体验中', totalCheckIns:0, streakDays:0 }
else {
  token = getStorageSync('token'); savedUser = getStorageSync('userInfo')
  if (!token || !savedUser || savedUser.name === '用户') → isGuest = true, userInfo = null
  else → isGuest = false, userInfo = savedUser
}
```

### 6.2 统计数据计算（`loadData`）

```js
const totalDays = records.length
const sleepDurations = records.filter(r => r.sleepDuration).map(r => r.sleepDuration)

const weekAvgSleep = sleepDurations.length > 0
  ? sleepDurations.slice(-7).reduce((a, b) => a + b, 0) / Math.min(7, sleepDurations.length)
  : null

const monthAvgSleep = sleepDurations.length > 0
  ? sleepDurations.slice(-30).reduce((a, b) => a + b, 0) / Math.min(30, sleepDurations.length)
  : null

healthScore: null   // 注释：需要 AI 分析才能得出
```

- 展示时：`stats.weekAvgSleep` 取 `toFixed(1) + 'h'`，否则显示「待测量」；`stats.totalDays` 显示 `${totalDays}天` 或 `0天`
- 健康评分显示 `stats.healthScore || '待分析'`

### 6.3 日期匹配规则

```
getCheckInRecord(date): date.toISOString().split('T')[0] === record.date
```

### 6.4 徽章规则（硬编码）

| 徽章 | 解锁条件（描述） | 初始状态 | 进度 |
|------|------------------|----------|------|
| 打卡达人 | 连续打卡 7 天 | unlocked | 100% |
| 守护天使 | 守护 30 天 | unlocked | 100% |
| 健康先锋 | 完成健康评估 | unlocked | 100% |
| 睡眠大师 | 打卡 30 天 | 进行中 | 60% |
| 超级守护 | 守护 365 天 | 锁定 | — |
| 更多徽章 | 即将推出 | 占位 | — |

汇总文案固定为「已解锁 3 / 6 个徽章」。注：徽章状态为静态写死，未与真实打卡数据联动。

- **加载策略**：先取绑定列表，再 `Promise.all` 并发拉取每个长辈的状态；任一失败均降级到默认值，不影响其他长辈

## 6. 业务规则

### 6.1 睡眠质量维度

```js
// 平均睡眠时长（checkIns 中 sleepDuration 单位为分钟）
const avgDuration = checkIns.reduce((sum, c) => sum + (c.sleepDuration || 0), 0) / checkIns.length
const avgDurationHours = Math.round(avgDuration / 60 * 10) / 10

status: avgDurationHours >= 7 && avgDurationHours <= 9 ? 'good'
      : avgDurationHours > 0 ? 'warning' : 'empty'
trend: 'stable'
description: avgDurationHours > 0 ? `本周平均${avgDurationHours}小时` : '暂无睡眠记录'

// 睡眠效率（理想睡眠 8 小时）
const efficiency = avgDurationHours > 0 ? Math.min(100, Math.round(avgDurationHours / 8 * 100)) : null
status: efficiency >= 85 ? 'good' : 'warning'
description: '基于入睡与起床时间计算'
```

无数据时：`duration` value=null / status=`empty` / description「请完成睡觉/起床打卡以记录睡眠数据」；`efficiency` value=null / `empty` /「暂无数据」。

### 6.2 作息节律维度

```js
// 起床时间偏差（标准差，单位分钟）
const avgWakeDeviation = calculateTimeDeviation(wakeTimes)
status: avgWakeDeviation <= 30 ? 'good' : avgWakeDeviation <= 60 ? 'warning' : 'danger'
description: avgWakeDeviation <= 30 ? '起床时间很规律' : '建议固定起床时间'

// 打卡完成率
const daysWithData = checkIns.length
const completionRate = Math.round(daysWithData / 7 * 100)
status: completionRate >= 80 ? 'good' : completionRate >= 50 ? 'warning' : 'empty'
trend: completionRate >= 80 ? 'up' : 'stable'
description: `本周已打卡${daysWithData}天`
```

**时间偏差算法（原样）**：

```js
const calculateTimeDeviation = (times: string[]): number => {
  // 将时间字符串转换为分钟数
  const minutes = times.map(t => {
    const [h, m] = t.split(':').map(Number)
    return h * 60 + m
  })
  // 计算标准差
  const avg = minutes.reduce((sum, m) => sum + m, 0) / minutes.length
  const variance = minutes.reduce((sum, m) => sum + Math.pow(m - avg, 2), 0) / minutes.length
  return Math.round(Math.sqrt(variance))
}
```

无数据时：`wake` null/`empty`/「请完成打卡以记录作息数据」；`checkin` value=`'0'` / `empty` /「本周暂无打卡记录」。

### 6.3 活动状态维度

```js
const totalSteps = activityData.reduce((sum, d) => sum + (d.steps || 0), 0)
const avgSteps = activityData.length > 0 ? totalSteps / activityData.length : 0

// 日均步数（仅 totalSteps > 0 时生成）
value: Math.round(avgSteps)
status: avgSteps >= 6000 ? 'good' : avgSteps >= 3000 ? 'warning' : 'danger'
description: avgSteps >= 6000 ? '活动量充足' : '建议增加运动'

// 户外时长（分钟，仅 totalOutdoor > 0 时生成）
const totalOutdoor = activityData.reduce((sum, d) => sum + (d.outdoorTime || 0), 0)
status: totalOutdoor >= 30 ? 'good' : 'warning'
description: totalOutdoor >= 30 ? '户外活动充足' : '建议多户外活动'

// 久坐时长（小时，仅 avgSedentary > 0 时生成）
const totalSedentary = activityData.reduce((sum, d) => sum + (d.sedentaryTime || 0), 0)
const avgSedentary = activityData.length > 0 ? totalSedentary / activityData.length : 0
```

### 6.5 评分算法（原样）

```js
// 分类评分：把状态映射为分数后取平均
const calculateCategoryScore = (metrics: HealthMetric[]): number | null => {
  const validMetrics = metrics.filter(m => m.value !== null && m.status !== 'empty')
  if (validMetrics.length === 0) return null

  const scores = validMetrics.map(m => {
    switch (m.status) {
      case 'good': return 100
      case 'warning': return 70
      case 'danger': return 40
      default: return 0
    }
  })

  return Math.round(scores.reduce((sum, s) => sum + s, 0) / scores.length)
}

// 综合评分：所有非空分类评分的平均值
const calculateOverallScore = (categories: HealthCategory[]): number | null => {
  const validCategories = categories.filter(c => c.score !== null)
  if (validCategories.length === 0) return null

  return Math.round(validCategories.reduce((sum, c) => sum + (c.score || 0), 0) / validCategories.length)
}
```

```js
const parseAIInsights = (content: string): AIInsight[] => {
  const paragraphs = content.split('\n').filter(p => p.trim().length > 10)

  return paragraphs.slice(0, 5).map((p, index) => {
    let type: 'observation' | 'analysis' | 'suggestion' = 'observation'
    let priority: 'high' | 'medium' | 'low' = 'medium'

    if (p.includes('建议') || p.includes('应该') || p.includes('推荐')) {
      type = 'suggestion'
    } else if (p.includes('分析') || p.includes('原因') || p.includes('因为')) {
      type = 'analysis'

    if (p.includes('注意') || p.includes('警告') || p.includes('重要') || p.includes('立即')) {
      priority = 'high'
    } else if (p.includes('良好') || p.includes('正常') || p.includes('稳定')) {
      priority = 'low'
    }

    return { id: `ai-${index}`, type, content: p.trim(), priority }
  })
}
```

## 6. 业务规则

### 6.1 时段划分规则（原样）

```js
const getTimePeriod = (time: string): 'morning' | 'afternoon' | 'evening' => {
  const hour = parseInt(time.split(':')[0])
  if (hour < 12) return 'morning'
  if (hour < 18) return 'afternoon'
  return 'evening'
}
```

即：`[00:00, 12:00)` → 晨起；`[12:00, 18:00)` → 午后；`[18:00, 24:00)` → 睡前。

### 6.2 今日服药状态计算（原样）

```js
const calculateTakenToday = (reminderId: string, _times: string[], records: any[]) => {
  const result = { morning: false, afternoon: false, evening: false }
  records.forEach(record => {
    if (record.reminder_id === reminderId && record.taken) {
      const period = getTimePeriod(record.scheduled_time || '08:00')
      result[period] = true
    }
  })
  return result
}
```

### 6.3 统计计算（原样）

```js
const activeReminders   = reminders.filter(r => r.isActive)
const inactiveReminders = reminders.filter(r => !r.isActive)

const takenCount = reminders.reduce((acc, r) => {
  const takenTimes = r.times.filter(t => r.takenToday[getTimePeriod(t)]).length
  return acc + takenTimes
}, 0)

const totalTimes = reminders.filter(r => r.isActive).reduce((acc, r) => acc + r.times.length, 0)
```

- 展示为：已服用 `takenCount` / 待服用 `totalTimes - takenCount` / 总计 `totalTimes`

### 6.4 记录服药的时间取值

```js
const time = reminder.times.find(t => getTimePeriod(t) === period) || '08:00'
```

### 6.5 已知限制（还原时需注意）

- `takenToday` 只区分三个时段，**同一时段的多个时间点共用同一标记**；例如 `['08:00','10:00','14:00']` 中 08:00 与 10:00 同属 `morning`，标记一次两者均显示「已服用」
- `settings` 中的 `repeatCount: 3` 与 `repeatInterval: 5` **未在 UI 中暴露**，仅存在于状态与 Storage
- 统计中 `takenCount` 统计的是**所有提醒（含已暂停）**，而 `totalTimes` 只统计**进行中的提醒**，因此暂停提醒较多时可能出现 `待服用` 为负数

## 6. 业务规则

### 6.1 手机号校验（原样）

```js
const phoneRegex = /^1[3-9]\d{9}$/
if (!phoneRegex.test(editValue.trim())) {
  Taro.showToast({ title: '手机号格式不正确', icon: 'error' })
  return
}
```

### 6.2 昵称校验

- 空值（`!newNickname.trim()` / `!editValue.trim()`）→ toast「昵称不能为空」

### 6.3 极简模式开关的确认与回滚

```
onCheckedChange(checked):
  setConfig({ enabled: checked })
  setSettings(prev => ({ ...prev, simpleMode: checked }))
  if (checked):
     showModal('开启极简模式', '将使用更大字体和简化界面，方便长辈使用')
       确认 → toast「已开启」
       取消 → setConfig({ enabled: false })
              setSettings(prev => ({ ...prev, simpleMode: false }))
  else:
     toast「已关闭」
```

### 6.4 退出登录清理规则

```
清除项：isLoggedIn = false、userNickname = ''、userPhone = ''
延时 1500ms 后 switchTab 回首页
```

### 6.5 未实现 / 占位行为

| 项 | 现状 |
|----|------|
| 账号注销 | 确认后仅 toast「请联系客服处理」，无实际注销逻辑 |
| 数据可见范围 | 仅 toast 反馈，未写入 Storage 或状态 |
| 夜间模式 / 自动打卡 / 隐私模式 / 位置共享 | 仅保存布尔值到 `userSettings`，无对应的实际功能实现 |
| `settings.fontSize` | 存在于状态与默认值（`'normal'`），但**页面无 UI 入口** |
| 「绑定」按钮显示条件 | 判断 `userInfo.phone === '未绑定手机'`，而初始值为 `''`，条件恒为假（推测为缺陷） |
