### 3. 交互行为

| 操作 | 结果 |
|---|---|
| 点击任一 tab | `setActiveTab(...)`，仅切换下方表单区，手机号 state 共享不重置 |
| 点击"获取验证码" | 校验手机号必须 11 位 → 不满足 toast"请输入正确的手机号"；`countdown > 0` 时直接 return（防重发）；否则 POST `/api/auth/send-code`，`code === 200` 时 toast"验证码已发送"并 `setCountdown(60)` 开始倒计时 |
| 倒计时 | `useEffect` 监听 `countdown`，>0 时每秒 -1，按钮文字变"N秒后重发"并置灰 |
| 点击"登录"（验证码） | 校验顺序：协议勾选 → 手机号 11 位 → 验证码 ≥4 位，任一失败 toast 提示。通过后 POST `/api/auth/login`，成功：写 `token` 与 `userInfo{id,phone,name,role}` 到 Storage，toast"登录成功"，**1500ms 后 `Taro.navigateBack()`** |
| 点击"登录"（密码） | 校验：协议 → 手机号 11 位 → 密码 ≥6 位。POST `/api/auth/login-password`，成功后 **1500ms 后 `Taro.switchTab` 到 `/pages/home/index`**（与验证码登录的返回行为不同） |
| 点击眼睛图标 | 切换 `showPassword`，控制密码明文/密文 |
| 点击"忘记密码？" | `navigateTo` → `/pages/forgot-password/index` |
| 点击"微信一键登录" | 先校验协议；再判 `Taro.getEnv() !== ENV_TYPE.WEAPP` 则 toast"微信登录仅在小程序可用"并中断；否则 `Taro.login()` 拿 code → POST `/api/auth/wechat-login`，成功写法同验证码登录（`navigateBack`） |
| 点击勾选框行 | 切换 `agreementChecked`；未勾选时登录/微信按钮有 `.disabled-btn`（`opacity:.5; box-shadow:none`），但**点击仍会触发函数**，由函数内部 toast 拦截 |
| 点击三份协议 | 分别 `navigateTo` 到 `/pages/user-agreement/index`、`/pages/privacy-policy/index`、`/pages/voiceprint-agreement/index` |
| 按钮按下态 | `.login-btn/.wechat-btn/.code-btn:not(.disabled)/.tab-item:active` → `transform:scale(0.98); opacity:0.9` |

### 4. 状态与数据（8 个 useState）

| state | 类型 | 含义 |
|---|---|---|
| `phone` | `string` | 手机号输入值（两个 tab 共用） |
| `code` | `string` | 验证码输入值 |

### 5. 样式特征

- 页面底色：`linear-gradient(180deg,#F4EFE6 0%,#EDE8DF 100%)`，`min-height:100vh`，内边距 `60px 32px 40px`
- 主色 `#8FA68E`、渐变终点 `#9DB89C`；深色文字 `#2F3A2F`；次要文字 `#7D746B`；链接蓝 `#1890FF`；微信绿 `#07C160`
- 圆角：LOGO 48px、Tab 胶囊 32px、Tab 项 24px、输入框/按钮/微信按钮 20px、勾选框 14px、协议容器 16px
- 阴影：LOGO `0 8px 24px rgba(143,166,142,.25)`、Tab 容器 `0 2px 8px rgba(0,0,0,.04)`、输入框 `0 2px 8px rgba(0,0,0,.04)`、登录按钮 `0 6px 20px rgba(143,166,142,.25)`、微信按钮 `0 6px 20px rgba(7,193,96,.25)`
- 字号：品牌名 28px、Slogan/标签/Tab/提示 16px、输入框 18px、按钮 18px、协议与倒计时 14px
- 间距：品牌区下 48px、Tab 下 40px、表单内 gap 24px、输入组内 gap 12px、协议区上 40px
- 动画：`logo-float` 3s 上下浮动 8px

### 6. 业务规则

- **手机号校验**：`phone.length !== 11` 即判错
- **验证码校验**：登录时要求 `code.length >= 4`（未强制 6 位）
- **密码校验**：`password.length >= 6`
- **倒计时规则**：固定 60 秒，`countdown > 0` 期间禁止重发
- **协议强校验**：三个登录入口（手机验证码 / 密码 / 微信）进入业务逻辑前**都先判 `agreementChecked`**，未勾选直接 toast"请先同意用户协议和隐私政策"
- **登录后跳转差异**：验证码登录与微信登录使用 `navigateBack()`；密码登录使用 `switchTab('/pages/home/index')`
- **接口清单**：`POST /api/auth/send-code`、`POST /api/auth/login`、`POST /api/auth/login-password`、`POST /api/auth/wechat-login`

## register — 注册页

**文件**：`register\index.tsx`（299 行）、`register\index.css`（173 行）

### 1. 页面角色

新用户注册页，采用**分步（Step）流程**：先验证手机号，再选身份并填姓名，完成后写入本地用户信息并跳首页。

### 2. 布局结构

整页 `.register-page`：`padding:0 16px 24px`、`min-height:100vh`、背景蓝色渐变 `linear-gradient(180deg,#f0f9ff 0%,#ffffff 100%)`、纵向 flex。从上到下：

**① 顶部导航行**（JSX 用原子类，非 CSS 里的 `.register-nav`）
- 横向 flex、`items-center`、下边距 24px（`mb-6`）
- 左：返回箭头 `ArrowLeft`（24px，`#6b7280`），可点击
- 右：标题"新用户注册"，20px / 600 / 左缩进 16px（`ml-4`）

**② 步骤指示器 `renderStepIndicator()`**
- 横向居中（`flex flex-row items-center justify-center mb-6`）
- 三个圆形步骤点 1-2-3（`w-8 h-8 rounded-full`，即 32×32，文字 14px）
  - 已到达（`s <= step`）：底色 `bg-blue-500`，文字白
  - 未到达：底色 `bg-gray-200`，文字 `text-gray-500`
- 点与点之间：连接条 `w-12 h-1`（48×4px），`s < step` 为 `bg-blue-500`，否则 `bg-gray-200`
- ⚠️ 注意：`step` 实际只会是 1 或 2（第三个点永远达不到"点亮"状态，因为 `completeRegister` 直接跳走）

**③ 步骤 1 卡片 `renderStep1()`（step === 1）**

- "下一步"按钮：`Button className="w-full mt-4"`（占满宽、上边距 16px），白色文字；`loading || !codeSent` 时禁用 —— **必须先成功发送过验证码才能点**

**④ 步骤 2 卡片 `renderStep2()`（step === 2）**
- 标题"选择身份"（`text-lg font-semibold mb-4`）
- **身份选择：横向两卡片并排**（`flex flex-row gap-4 mb-4`）

### 3. 交互行为

| 操作 | 结果 |
|---|---|
| 点击返回箭头 `goBack()` | `step > 1` 时退回到上一步（`setStep(step-1)`）；`step === 1` 时 `Taro.navigateBack()` |
| 点击"获取验证码" `sendCode()` | 校验手机号 11 位 → 不满足 toast"请输入正确的手机号"；POST `/api/auth/send-code`；**判 `res.statusCode === 200`**（注意与 login 页判 `res.data.code` 不同）→ 成功：`setCodeSent(true)`、`setCountdown(60)`、toast"验证码已发送" |
| 倒计时 | `useEffect` 每秒递减，按钮文字变 `Ns` 并禁用 |
| 点击"下一步" `verifyCode()` | 校验 `code.length !== 6` → toast"请输入6位验证码"；POST `/api/auth/verify-code`；`statusCode === 200` → `setStep(2)` + toast"验证成功"。**未勾选禁用条件时按钮被 disabled** |
| 点击"我是长辈" / "我是家属" | `setRole('elder')` / `setRole('family')`，切换卡片高亮与图标颜色 |
| 点击"完成注册" `completeRegister()` | 校验 `!name` → toast"请输入姓名"；POST `/api/auth/register`（body: `{phone, code, name, role}`）；`statusCode === 200` 时写入 `userId / userName / userRole / userPhone` 到 Storage，toast"注册成功"，**1500ms 后 `Taro.switchTab('/pages/home/index')`** |
| 请求失败 | 各步骤均有 `catch`，toast"发送失败"/"验证失败"/"注册失败" |

### 4. 状态与数据（8 个 useState）

| state | 类型 | 含义 |
|---|---|---|
| `step` | `number` | 当前步骤，初始 1（实际只有 1、2） |
| `phone` | `string` | 手机号 |

| `name` | `string` | 用户姓名 |

### 6. 业务规则

**① 睡眠评分算法（原文照抄）**
```js
const calculateSleepScore = () => {
  if (!sleepDuration) return 0
  if (sleepDuration >= 7 && sleepDuration <= 9) return Math.min(95 + (sleepDuration - 7) * 2, 100) // 7-9小时最优
  if (sleepDuration >= 6 && sleepDuration < 7) return 70 + (sleepDuration - 6) * 20 // 6-7小时一般
  if (sleepDuration > 9) return 80 // 过长
  return Math.max(50, sleepDuration * 10) // 不足
}
```
分档归纳：
| 睡眠时长 | 得分公式 | 上限 |
|---|---|---|
| 7–9 小时 | `min(95 + (h-7)*2, 100)` | 100 |
| 6–7 小时 | `70 + (h-6)*20` | 90 |
| > 9 小时 | 固定 `80` | 80 |
| < 6 小时 | `max(50, h*10)` | 60 |
| 无数据 | `0` | — |

**② 睡眠质量文案（原文照抄）**
```js
const getSleepQualityText = () => {
  if (!sleepDuration) return '待测量'
  if (sleepDuration >= 7 && sleepDuration <= 9) return '良好'
  if (sleepDuration >= 6 && sleepDuration < 7) return '一般'
  if (sleepDuration > 9) return '过长'
  return '不足'
}
```

**③ 睡眠时长计算**
```js
const sleepDuration = sleepStartTime && wakeStartTime
  ? (wakeStartTime.getTime() - sleepStartTime.getTime()) / (1000 * 60 * 60)
  : null
```
起床打卡时同样公式：`const duration = (now.getTime() - sleepStartTime.getTime()) / (1000 * 60 * 60)`

**④ 打卡状态机（三条互斥守卫）**
- 睡觉打卡前置条件：**不能处于"已睡着未起床"状态**
- 起床打卡前置条件：**必须已有 sleepStartTime**，且 **必须尚未 wakeStartTime**
- 开始新一轮前置条件：**必须已存在 sleepStartTime 且已存在 wakeStartTime**
- 即完整闭环：`未睡 → (睡觉打卡) → 睡中 → (起床打卡) → 已完成 → (开始新一轮) → 未睡`

**⑤ 日期格式规则**
- `formatDate(date)` → `MM/DD`（补零）— 用于记录 `date` 字段与周历匹配
- `getTodayDateString()` → `YYYY年MM月DD日` — 用于页面标题
- `formatTime(date)` → `HH:mm`（补零），空值返回 `'--:--'`
- 周历：以今天为基准 **i 从 -3 到 +3** 共 7 天，`hasRecord` 由 `checkInRecords.some(r => r.date === dateStr)` 判定
- 星期文案：`['一','二','三','四','五','六','日'][day.getDay() === 0 ? 6 : day.getDay() - 1]`

**⑥ 数据加载优先级（活动数据）**
1. 先调 `weRunService.getTodaySteps()`（微信运动），`steps > 0` 则采用，`outdoorTime` 固定给 `30`，并**异步** `syncToServer` 后 **return**
2. 微信步数拿不到才回落 `GET /api/statistics/daily`，取 `steps/distance/calories/outdoorTime`

**⑦ 存储读写规则**
- 打卡记录读入时需要把字符串日期反序列化为 `Date` 对象：`sleepTime: new Date(r.sleepTime)`、`wakeTime: r.wakeTime ? new Date(r.wakeTime) : null`
- 读入后若找到"今天"的记录，回填 `sleepStartTime` / `wakeStartTime`（实现刷新后状态不丢）
- 用药提醒无 Storage 数据时写入 3 条默认值

**⑧ 硬编码的展示常量（还原时注意，这些不是算出来的）**
- 评分环右上角标签固定"**优秀**"
- "今日睡眠时长 **7小时32分**"
- "深度睡眠占比 **35% 💫**"
- 运动目标"**已完成 65%**"与进度条宽 `65%`

**⑨ 提醒配置项默认值**：由 `checkinReminderService.getConfig()` 提供，含 `enabled`、`sleepTime`、`sleepReminderMinutes`、`wakeTime`、`wakeReminderMinutes`

### 3. 交互行为

**SOS 求救完整链路（核心）**

| 步骤 | 行为 |
|---|---|
| 1. 长按 SOS 按钮 | `onTouchStart` → `handleSOSPressStart()`：`setInterval` 每 **100ms** 让 `progress += 10`，同步写入 `sosHoldProgress` |
| 2. 达到 100% | 清除定时器 → `startSOSCountdown()`：`setShowSOSCountdown(true)`、`setSosCountdown(5)`、**`Taro.vibrateShort({type:'heavy'})` 震动反馈**，开始每秒倒计时 |
| 3. 倒计时到 0 | 自动 `clearInterval` → 关弹窗 → `triggerSOS()` |
| 4a. 提前松手 | `onTouchEnd` → `handleSOSPressEnd()`：清除定时器并把 `sosHoldProgress` 归零（**长按必须一口气满 3 秒**） |
| 4b. 点"取消求救" | `cancelSOSCountdown()`：清定时器、关弹窗、`sosCountdown` 复位 5、`sosHoldProgress` 归零、toast"已取消求救" |
| 4c. 点"立即发送" | `immediateTriggerSOS()`：清定时器、关弹窗、直接 `triggerSOS()` |
| 5. `triggerSOS()` | ① `setSosProgress('triggering')` + `setSosActive(true)`；② `SoundService.playSOSAlert()` 播放警报音；③ `setSosProgress('sending')`；④ 位置取 `currentLocation || elderStatus.locationCoords`；⑤ `await sosService.sendSOS({type:'sos_button', location, message:'用户主动发起一键SOS求救'})` |
| 6. 发送成功 | `setSosProgress('notified')` → 取 `familyService.getEmergencyContacts()` 前 2 位姓名拼接 → toast「已通知张三、李四等N位家属」（success，**duration 3000**）→ `await sosService.startLocationTracking(30)`（**30 秒间隔追踪**）→ **3 秒后** `setSosProgress('waiting')` |
| 7. 发送失败 | `Taro.showModal`「通知失败 / 未能成功通知家属，请手动拨打紧急联系人电话」，确认按钮"查看联系人" → 跳 `/pages/member-bind/index`；同时状态回滚 `idle` + `sosActive=false` |
| 8. 异常 | catch → toast"求救信号发送失败"，状态回滚 |
| 9. 点"解除求救"（waiting 态） | `handleResolveSOS()` → `setShowSOSConfirm(true)` |
| 10. 弹窗确认解除 | `confirmResolveSOS()`：`setSosProgress('resolved')`、`sosActive=false`、关弹窗 → `await sosService.cancelSOS()` → `sosService.stopLocationTracking()` → **2 秒后** `setSosProgress('idle')` |

### 6. 业务规则

**① SOS 长按计时算法（原文照抄）**
```js
const handleSOSPressStart = () => {
  setSosHoldProgress(0)
  let progress = 0
  sosHoldTimerRef.current = setInterval(() => {
    progress += 10
    setSosHoldProgress(progress)
    if (progress >= 100) {
      clearInterval(sosHoldTimerRef.current!)
      startSOSCountdown()
    }
  }, 100)
}
```
等价于：**每 100ms 增 10%，共 10 次 = 1000ms**。注意 UI 文案写的是"长按3秒"，而代码实际只需 **1 秒**满进度 —— 这是文案与实现的**不一致点**，还原时需按需求方确认取 1s 还是 3s。

**② SOS 倒计时兜底规则**：倒计时 5 秒，结束后**无条件自动发送**（防用户失去意识无法确认），提供"取消求救"和"立即发送"两个出口。

**③ SOS 进度环渲染公式**：`transform: rotate(${sosHoldProgress * 3.6 - 90}deg)` —— 把 0–100 映射到 -90°–270°。

**④ 位置追踪间隔**：`sosService.startLocationTracking(30)`，即成功后每 **30 秒**上报一次位置。

**⑤ 状态流转时序**：`notified` 停留 3 秒 → `waiting`；`resolved` 停留 2 秒 → `idle`。

**⑥ 相对时间格式化（原文照抄）**
```js
const getAlertTimeText = (timestamp: number) => {
  const diff = Date.now() - timestamp
  const minutes = Math.floor(diff / 60000)
  if (minutes < 60) return `${minutes}分钟前`
  const hours = Math.floor(minutes / 60)
  if (hours < 24) return `${hours}小时前`
  return `${Math.floor(hours / 24)}天前`
}
```

**⑦ 活动时长格式化（原文照抄）**
```js
const formatActivityTime = (minutes: number) => {
  const hours = Math.floor(minutes / 60)
  const mins = minutes % 60

```
例：`155` → "2小时35分"。

**⑧ 警报图标选择规则**
```js
const getAlertIcon = (_type: string, level: AlertLevel) => {
  if (level === 'urgent') return <ShieldAlert size={20} color="#E85A5A" />
```

**⑨ 警报标题规则**：`alert.type === 'fall'` → "跌倒警报"，其余一律"长时间未活动"（**二值硬编码**，未覆盖 `sos/health/device/voice/video/sedentary` 等类型）。

**⑩ 警报过滤规则**：列表只显示 `resolved === false` 的项；"忽略" = 软删除（置 `resolved`）。

### 3. 交互行为

**平台检测**：`useEffect` 中 `Taro.getEnv()` 判定 `isWeapp`（WEAPP）与 `isTT`（TT），`isMiniApp = isWeapp || isTT`，用于分支渲染与功能开关。

| 操作 | 结果 |
|---|---|
| 页面 ready（`useReady`） | 小程序环境下调 `checkPermissions()` 检测录音/相机/定位三项权限 |
| 切换「实时跌倒监测」开关 | **开**：`fallDetectionService.onFallDetected(cb)` 注册回调（检测到跌倒 → `setFallDetectionStatus('alert')` + **自动调 `handleEmergencySOS()`**）+ `fallDetectionService.startMonitoring()`；**关**：`stopMonitoring()` + 状态复位 `normal` |
| 点击「获取位置」 | `getCurrentLocation()`，H5 与小程序走**两套不同逻辑**（见下方规则） |
| 点击「开始追踪 / 停止追踪」 | 切换 `trackingEnabled`；`useEffect` 监听该值：为真且是小程序 → `startLocationTracking()`（**每 30 秒**调一次 `getCurrentLocation`，并立即先取一次）；否则 `stopLocationTracking()` |
| 点击权限提示条 | 分别调 `requestRecordPermission()` / `requestCameraPermission()` / `requestLocationPermission()` |
| 点击「开始录音」 | 先查 `permissions.record`，未授权先 `requestRecordPermission()`（失败则中断）；通过则 `recorderManagerRef.current.start(RECORD_CONFIG)` |
| 点击「停止录音」 | `recorderManagerRef.current.stop()` → 触发 `onStop` 回调 → `handleRecordStop(res)` |
| 录音自动停止 | 计时器到 **60 秒**自动调 `stopRecording()` |
| 录音结束处理 | 若 `res.duration < 1000`（不足 1 秒）→ toast"录音时间太短"并 return；否则 `showLoading('语音识别中...')` → `Network.uploadFile({url:'/api/monitor/voice-analyze', name:'audio'})`；成功则 `setVoiceText(data.text)` 并追加结果；**失败降级**为固定模拟文本"今天感觉有点累，睡眠质量不太好" + 分析"检测到您提到疲劳和睡眠问题，建议注意休息，保持规律作息。" + 告警"睡眠质量需关注" |
| 点击「健康分析 / 跌倒检测」tab | `setDetectMode(...)`，仅切换模式，不重新拍照 |
| 点击「拍照分析 / 跌倒检测」（大按钮） | `takePhoto()`：先校验相机权限 → 校验 `cameraReady`（否则 toast"摄像头未就绪"）→ `showLoading` → `Taro.createCameraContext().takePhoto({quality:'normal'})` → `setCapturedImage` → 按模式选接口（fall → `/api/monitor/fall-detect`；health → `/api/monitor/image-analyze`）→ `Network.uploadFile` |
| 跌倒检测命中 | 解析 `fallDetected` / `confidence`（缺省 85）/ `analysis`（缺省"姿态正常"）→ 写入 `fallResult` → 追加结果 → **若 `fallDetected` 为真**：`Taro.showModal`「跌倒风险告警 / 置信度: X%\n建议立即联系长辈确认状态」，确认按钮"立即联系" → 跳 `/pages/sos-map/index`；取消"稍后处理" |
| 拍照失败 | catch → 追加结果"已拍摄画面 / 服务暂时不可用" |
| 点击「重新拍摄」 | 清空 `capturedImage` 和 `fallResult`，摄像头预览恢复 |
| 点击「AI分析」（已拍图） | 再次调 `takePhoto()`（会重新拍一张再分析） |
| 点击「提交分析」 | `submitText()`：空输入 toast"请输入健康状态"；`showLoading('分析中...')` → POST `/api/monitor/text-analyze` `{content}` → 追加结果 + **清空输入框**；失败降级为"状态记录成功，AI分析服务暂时不可用" |
| 手动触发 SOS（内部函数 `handleEmergencySOS`） | `Taro.showModal`「紧急求助 / 是否立即发送紧急求助信号给家属？」→ 确认 → `Taro.getLocation({type:'gcj02'})`（失败容忍为 null）→ toast"紧急求助已发送" → POST `/api/emergency/sos` `{type:'manual_sos', location, timestamp}`。**注意：该函数只被"实时跌倒监测"回调调用，页面上没有可见的手动 SOS 按钮** |
| 页面卸载 | 清理 `recordingTimerRef` 和 `locationTimerRef`，并 `fallDetectionService.stopMonitoring()` |

**录音管理器回调绑定**：`onStart` → 状态 `recording` + 启动计时；`onPause` → `paused` + 停计时；`onResume` → `recording` + 重启计时；`onStop` → `idle` + 停计时 + `handleRecordStop`；`onError` → `idle` + 停计时 + toast"录音失败，请重试"。

**类型定义**
```ts
type RecordingState = 'idle' | 'recording' | 'paused'

interface AnalysisResult {
  type: 'text' | 'voice' | 'image' | 'fall' | 'location'
  content: string
  analysis: string
  alert?: string
  confidence?: number
  timestamp: number
}

interface LocationInfo {
  latitude: number
  longitude: number
  accuracy: number
  address?: string
  safeZone?: boolean
}

interface PermissionStatus {
  record: boolean | null   // null = 未检测
  camera: boolean | null
  location: boolean | null
}
```

```ts
const RECORD_CONFIG: Taro.RecorderManager.StartOption = {
```

### 6. 业务规则

**① 权限检测规则**：`Taro.getSetting()` 一次性读三项，取值 `authSetting['scope.record'|'scope.camera'|'scope.userLocation']`，用 `?? false` 兜底为 `false`（即**未授权与未检测都可能落到 false**）。

**② 三套权限申请的分支差异**
- `requestRecordPermission()` / `requestCameraPermission()`：`Taro.authorize({scope})` 成功置 `true`；失败 `showModal` 引导 → `Taro.openSetting()`
- `requestLocationPermission()`：**先判 `!isMiniApp`** —— H5 直接 `Taro.getLocation`（浏览器自动弹权限），失败 toast"定位失败，请检查浏览器定位权限"；小程序走 `Taro.authorize({scope:'scope.userLocation'})`，失败引导去设置

**③ 录音时长约束**
- 最大时长 **60 秒**（`RECORD_CONFIG.duration`，同时计时器也在 60 秒强制 `stopRecording()`）
- 最短有效时长 **1000ms**，不足则丢弃并提示"录音时间太短"
- 采样率 16000、单声道、比特率 48000、mp3

**④ 录音计时文案格式（原文照抄）**
```js
const formatTime = useCallback((seconds: number) => {
  const mins = Math.floor(seconds / 60)
  const secs = seconds % 60
  return `${mins.toString().padStart(2, '0')}:${secs.toString().padStart(2, '0')}`
}, [])
```
输出 `MM:SS`。

**⑤ 定位逻辑双分支**

*H5 分支*（`!isMiniApp`）：
1. `showLoading('获取位置...')`
2. `Taro.getLocation({type:'gcj02'})`
3. 构造 `LocationInfo`：`address` 直接拼坐标 `` `位置: ${lat.toFixed(4)}, ${lng.toFixed(4)}` ``，`safeZone` **恒为 `true`**
4. 置 state、把 `permissions.location` 置 `true`、toast"定位成功"
5. **异步尝试** POST `/api/monitor/location-trace/current-user`（失败静默忽略，不影响本地定位）
6. 兜底错误处理：错误信息含 `permission` 或 `权限` → 弹 Modal"定位权限被拒绝 / 请在浏览器设置中允许访问位置信息"；否则 toast"定位失败，请稍后重试"

*小程序分支*：
1. 先查权限，未授权则申请
2. `Taro.getLocation({type:'gcj02', altitude:true})`
3. 调 POST `/api/monitor/location-trace/current-user` **取地址**（`addrRes.data?.data || addrRes.data` 双层兼容），失败则 `address` 保持 `'未知位置'`
4. 构造 `LocationInfo`（`safeZone` 同样恒 `true`）
5. **追加一条 `type:'location'` 的分析结果**（content = 地址，analysis = `坐标: lat, lng`）
6. toast"定位成功"；失败 toast"定位失败，请检查权限"

**⑥ 位置追踪频率**：`setInterval(..., 30000)` —— **30 秒一次**，并在启动时立即执行一次。

**⑦ 文本上报规则**：必须非空（`trim()` 校验）；上限 **500 字**；提交成功后清空输入框。

**⑧ 跌倒检测结果解析规则**
```js
const fallDetected = data?.fallDetected ?? false
const confidence  = data?.confidence   ?? 85
const analysis    = data?.analysis     || '姿态正常'
```
即：`fallDetected` 缺省 `false`、`confidence` 缺省 **85**、`analysis` 缺省"姿态正常"。接口响应做 `data?.data || data` 双层兼容。

**⑨ 分析结果管理规则**
```js
const addAnalysisResult = (result: Omit<AnalysisResult, 'timestamp'>) => {
  const newResult: AnalysisResult = { ...result, timestamp: Date.now() }
  setResults(prev => [newResult, ...prev])   // 新结果插入队首
}
```
- 展示时 `results.slice(0, 5)`，**最多显示 5 条**
- React key 用 `result.timestamp`
- 页面级 `results` 状态**不持久化**，刷新即清空

**⑩ 结果类型标签映射（JSX 原文）**
```
result.type === 'text'  → 文本
result.type === 'voice' → 语音
result.type === 'image' → 图像
（fall / location 无标签渲染）
```

| `/api/monitor/voice-analyze` | uploadFile（字段名 `audio`） | 录音结束 |

**⑬ 已知实现问题（还原/重构时需注意）**
1. `fallDetectionService.onFallDetected` 回调内 `console.log('跌倒警报:', alert)` —— **`alert` 未定义**，会抛 `ReferenceError`；且 `handleEmergencySOS()` 写在 `if (result.detected)` 块**之外**，导致**每次回调（无论是否跌倒）都会触发 SOS 弹窗**。
2. 同样因为上面这行，`setFallDetectionStatus('alert')` 之后的代码实际不可达。
3. `detectMode` 初始值为 `'fall'`（跌倒检测），而非更常用的"健康分析"。
4. 「AI分析」按钮（已拍图状态）复用的是 `takePhoto()`，语义上是**重新拍照并分析**，而非分析已有图片。
5. 结果卡片的「分析结果」标题在 `CardTitle` 内又套了 `Text` 并写了 `block text-lg`，与 `.card-title` 的 18px 重复。
6. 页面顶部**没有**标题栏/返回键，也没有独立的 SOS 紧急按钮（只有内部函数）。
