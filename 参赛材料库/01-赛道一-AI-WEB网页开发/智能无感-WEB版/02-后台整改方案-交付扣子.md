## 一、核心设计：把后台升级为「AI 值守工作台」

### 1.1 产品定位重塑

**改造前**：数据管理后台（管理员看表、改状态）

**改造后**：**AI 值守工作台** —— 社区/机构守护员的值班台

**一句话价值**：

> 守护员不再逐条翻告警，AI 自动研判风险等级、解释原因、给出处置建议，人只做决策。

### 1.2 为什么这个定位成立

赛道一要求"AI 是核心而非附属"。在守护场景里，**告警研判本身就是 AI 天然该做的事**：

- 告警"14:32 跌倒检测触发"——是真的摔倒，还是坐下时误触发？
- 需要综合当日打卡、睡眠、用药、历史误报率来判断
- 这正是**多工具调用 + 推理**的场景

**这不是硬塞一个聊天框，是把 AI 放在业务流程的关键决策点上。**

### 1.3 改造后架构

#### 5 个工具定义（Function Calling 清单）

| # | 工具名 | 参数 | 返回 | 数据来源（已存在的接口） |
|---|---|---|---|---|
| 1 | `getUserProfile` | `userId` | 姓名、年龄、独居状态、家属绑定、设备 | `GET /admin/users/{id}` |
| 2 | `getRecentCheckins` | `userId, days` | 打卡率、连续未打卡天数、最近打卡时间 | `GET /api/checkin/records` |

**SSE 客户端**（注意：EventSource 不支持 POST，必须用 fetch + ReadableStream）：

```typescript
async function startTriage(alertId: string) {
  toolCalls.value = []
  verdict.value = null
  streamText.value = ''

  const resp = await fetch(`/api/admin/alerts/${alertId}/ai-triage`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${userStore.token}`,
    },
    body: JSON.stringify({ stream: true }),
  })

  const reader = resp.body!.getReader()
  const decoder = new TextDecoder()
  let buffer = ''

  while (true) {
    const { done, value } = await reader.read()
    if (done) break
    buffer += decoder.decode(value, { stream: true })

    const lines = buffer.split('\n\n')
    buffer = lines.pop() || ''

    for (const block of lines) {
      const eventMatch = block.match(/^event: (.+)$/m)
      const dataMatch = block.match(/^data: (.+)$/m)
      if (!eventMatch || !dataMatch) continue

      const event = eventMatch[1]
      const data = JSON.parse(dataMatch[1])

      switch (event) {
        case 'tool_call':
          toolCalls.value.push({ ...data, summary: '' })
          break
        case 'tool_result':
          const t = toolCalls.value.find(x => x.tool === data.tool)
          if (t) { t.status = 'done'; t.summary = data.summary }
          break
        case 'token':
          streamText.value += data.delta
          break
        case 'verdict':
          verdict.value = data
          break
        case 'done':
          break
      }
    }
  }
}
```

#### 安全约束（**必做**）

自然语言转 SQL 有注入风险，必须：

| 约束 | 实现 |
|---|---|
| **只读** | 生成的 SQL 必须以 `SELECT` 开头，其他一律拒绝 |
| **表白名单** | 只允许查询 `users`、`alerts`、`checkin_records`、`devices` |
| **禁止敏感字段** | 不允许 `SELECT *`，禁止查 `password`、`token` |
| **行数限制** | 自动追加 `LIMIT 1000` |
| **超时** | SQL 执行超时 5s |
| **审计** | 每条 SQL 写入 `call_logs` |

```java
private static final Set<String> ALLOWED_TABLES = Set.of(
    "users", "alerts", "checkin_records", "devices", "feedback"
);

public String validateSql(String sql) {
    String upper = sql.trim().toUpperCase();
    if (!upper.startsWith("SELECT")) throw new BizException("仅允许查询操作");
    if (upper.contains("INSERT") || upper.contains("UPDATE")
        || upper.contains("DELETE") || upper.contains("DROP")
        || upper.contains("ALTER") || upper.contains(";--")) {
        throw new BizException("检测到非法操作");
    }
    // 表名白名单校验...
    return sql + (upper.contains("LIMIT") ? "" : " LIMIT 1000");
}
```

## 五、关键技术注意事项（**扣子必读**）

### 5.1 SSE 不能用 EventSource

```typescript
// ❌ 错误：EventSource 不支持 POST 和自定义 Header
const es = new EventSource('/api/admin/alerts/1/ai-triage')

// ✅ 正确：fetch + ReadableStream
const resp = await fetch(url, { method: 'POST', headers: {...}, body })
const reader = resp.body.getReader()
```

### 5.2 后端 SSE 响应头

```java
@PostMapping(value = "/alerts/{alertId}/ai-triage",
             produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter triage(@PathVariable String alertId) {
    SseEmitter emitter = new SseEmitter(120_000L);  // 2 分钟超时
    // ...
    emitter.send(SseEmitter.event().name("tool_call").data(json));
    // ...
    emitter.complete();
    return emitter;
}
```

**必须配置**（否则 nginx 会缓冲导致不流式）：

```nginx
proxy_buffering off;
proxy_cache off;
proxy_read_timeout 300s;
```

### 5.3 复用现有 AiService

后端已有三层降级（`Ollama → Coze → 规则库`），**直接复用**：

```java
// AiService 现有签名
public ChatResult chat(String message, String conversationId, AiContext ctx)

// 研判场景调用示例
AiContext ctx = AiContext.builder()
    .userId(alert.getUserId())
    .scenario("triage")          // 新场景标识
    .build();
```

> ⚠️ 若现有 `AiService.chat()` 不支持 Function Calling，需要扩展。
> **扣子要先确认**：Ollama 的 qwen2.5 支持 tools 参数，Coze 支持插件调用。
> 若都不支持，退化为"提示词内置工具描述 + 先检索后生成"的伪工具调用——**仍可演示**。

### 5.4 不要破坏现有功能

现有 6 个页面（Dashboard/Users/Alerts/Feedback/Devices/System）**必须保持可用**。
改造是**新增能力**，不是重写。

### 5.5 密钥安全

**绝对不要**在代码里出现：
- `pat_` 开头的 Coze Token
- 微信 AppSecret
- 数据库密码

全部走环境变量（参考 `application.yml` 的 `${COZE_API_TOKEN:}` 写法）。

### 5.6 ⚠️ 需要新建 `call_logs` 表

**已核查：现有数据库 12 张表中没有 `call_logs`。** 方案的"可审计性"依赖它，必须先建表。

```sql
-- 追加到 db/V1__init_schema.sql 末尾
CREATE TABLE IF NOT EXISTS call_logs (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  ts            DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  log_type      VARCHAR(32)  NOT NULL COMMENT 'triage | query | rag | tool_call | llm_call',
  ref_id        VARCHAR(64)  COMMENT '关联ID：alertId / queryId',
  user_id       VARCHAR(64)  COMMENT '操作的管理员ID',
  target_user   VARCHAR(64)  COMMENT '被研判的老人ID',
  tool_name     VARCHAR(64),
  input_text    TEXT,
  output_text   TEXT,
  risk_level    VARCHAR(16)  COMMENT 'CRITICAL/HIGH/MEDIUM/LOW',
  confidence    DECIMAL(4,3),
  latency_ms    INT,
  status        VARCHAR(16)  DEFAULT 'ok' COMMENT 'ok/error/timeout/degraded',
  error_msg     TEXT,
  INDEX idx_ts (ts),
  INDEX idx_type (log_type),
  INDEX idx_target (target_user)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='AI 调用审计日志';
```

> 💡 **这张表直接对应"AI 安全与可控性 4%"和演示时的可审计性**。
> 演示时展示日志列表，证明每次 AI 研判都有据可查。

### 5.7 ✅ 现有表字段实测结果（**已核实，照此开发**）

> 以下字段是从 `db/V1__init_schema.sql` 实际读取的，**不是推测**。

#### `users` 表（关键：**没有 age 字段，用 birth_date**）

```sql
id              VARCHAR(36)   -- 用户ID（UUID）
phone           VARCHAR(20)
name            VARCHAR(128)
avatar          VARCHAR(512)
role            VARCHAR(20)   -- 'elder' 长辈 / 'family' 家属
birth_date      DATE          -- ★ 出生日期，年龄需在此计算
gender          VARCHAR(10)
address         TEXT
emergency_phone VARCHAR(20)   -- ★ 紧急联系电话
is_active       TINYINT(1)
is_admin        TINYINT(1)
created_at      DATETIME(3)
updated_at      DATETIME(3)
```

> ⚠️ **没有"是否独居"字段**。方案中的 `livingAlone` 需通过 `emergency_phone` 是否为空、
> 或 `family_bindings` 表记录数间接判断。**建议降级：不判独居，只报家属绑定数。**

> ⚠️ **`role` 是小写 `elder`/`family`**，不是大写 `ELDER`/`FAMILY`。
> 前端 `types/index.ts` 里写的是 `'ELDER' | 'FAMILY'`，是 `mapUser` 里转换过的，后端存的是小写。

#### `alerts` 表

```sql
id              VARCHAR(36)
user_id         VARCHAR(36)
alert_type      VARCHAR(30)   -- fall/sos/abnormal/...
severity        VARCHAR(20)   -- ★ 小写 low/medium/high/critical
title           VARCHAR(200)
description     TEXT
occurred_at     DATETIME(3)   -- ★ 注意不是 created_at
handled         TINYINT(1)
handled_by      VARCHAR(36)
handled_at      DATETIME(3)
notes           TEXT
created_at      DATETIME(3)
```

> ⚠️ **`severity` 后端存小写**，但前端 `AlertItem.severity` 类型是
> `'URGENT' | 'HIGH' | 'MEDIUM' | 'LOW'`。注意 `URGENT` 对应后端的 `critical`，且 `LOW` 前端的 `MEDIUM`…
> **扣子必须先读 `api/index.ts` 里的 `fromSeverity` / `mapAlert` 函数确认映射关系**，
> 不要重新发明一套。

## 附：5 个工具的实现参考

```java
@Component
public class UserProfileTool implements GuardianTool {
    public String name() { return "getUserProfile"; }
    public String description() {
        return "获取老人的档案信息，包括姓名、年龄、地址、绑定的家属数量、紧急联系电话、绑定设备。";
    }
    public Map<String, Object> parameters() {
        return Map.of("type", "object",
            "properties", Map.of("userId", Map.of("type","string","description","老人用户ID")),
            "required", List.of("userId"));
    }
    public ToolResult execute(Map<String, Object> args) {
        String userId = (String) args.get("userId");
        UserDetail user = adminService.getUserDetail(userId);

        // ⚠️ users 表没有 age 字段，用 birth_date 计算
        Integer age = user.getBirthDate() == null ? null
            : Period.between(user.getBirthDate().toLocalDate(), LocalDate.now()).getYears();

        // ⚠️ users 表没有 livingAlone 字段，用家属绑定数推断
        int familyCount = user.getFamilyCount();

        String summary = String.format("%s，%s岁，绑定家属%d人，紧急联系%s",
            user.getName(),
            age == null ? "年龄未知" : age + "",
            familyCount,
            StrUtil.isBlank(user.getEmergencyPhone()) ? "未设置" : "已设置");

        return ToolResult.ok(summary, user);
    }
}
```

> ⚠️ **注意**：`UserDetail` 实体目前可能没有 `birthDate` / `emergencyPhone` / `familyCount` 字段。
> 扣子需要在 `UserDetail` DTO 中补齐这三个字段，并在 `AdminController.getUserDetail` 里填充。
> **这是方案中唯一需要改动现有 DTO 的地方**，工作量约 30 分钟。

**其余 4 个工具结构相同，只是数据来源不同。**
