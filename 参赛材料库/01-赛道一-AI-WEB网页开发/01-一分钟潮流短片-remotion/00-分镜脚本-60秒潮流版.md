# 60 秒潮流短片 · 分镜脚本（Remotion）

> 作品：AI 节律守护 · 智能无感 —— 运营管理 Web 端（`guardian-admin`）
> 赛事：第九届传智杯 · 赛道一 AI WEB 网页开发
> 规格：1920×1080 / 30fps / 1800 帧 / 60 秒 / **无音频（纯视觉）**
> 风格：潮流科技短片 —— 深空黑底、霓虹青紫、大字报排版、快切卡点、玻璃拟态卡片
> 事实口径：全部数字取自《01-技术文档-七章.md》源码实测表，未实现能力（RAG / Agent / 视觉识别 / ASR·TTS）**一律不出现**

## 二、逐镜脚本

### S1｜Hook 跌倒｜0–8s｜240 帧
**画面**：黑场起，霓虹红橙光斑从底部涌起；三行大字依次砸入，每行带轻微横向拉伸与错位，字块之间有 4 帧白闪；网格在背景中缓慢漂移。

**文案（三行依次出现）**
1. `跌倒了。`（0.4s 起，白）
2. `手机，不在手边。`（2.6s 起，白）
3. `家里，没有人。`（4.8s 起，警示红）

**动效要点**
- 每行入场：`translateY` 40→0 + `clipPath` 遮罩 + `scaleX` 1.06→1，18 帧
- 第三行出现后，画面整体轻微抖动（`translateX` ±3px，正弦 6 帧周期）
- 6.8s 起三行同时向下压缩淡出，接闪白

**字幕**：无（大字即文案）

---

### S2｜Problem 链条断了｜8–17s｜270 帧
**画面**：画面中央一条水平链路，三个节点从左到右依次点亮：
`告警产生` → `消息推送` → `有人跟进`

- 前两个节点亮青色，第三个节点点亮瞬间变红并**断裂**（连线中间断开、碎片下坠）
- 右上角浮现大字 `然后呢？`
- 背景网格转为冷灰，光斑减弱

**文案**
- 主标题（左上）：`告警，不是终点`
- 中部大字（10.5s）：`然后呢？`
- 底部字幕：`AI 能发现异常，但异常之后，需要有人接住。`

**动效要点**
- 节点用 `spring` 弹出（damping 14）
- 第三个节点断裂：连线 `scaleX` 1→0.4 并位移，红色碎片 3 块下坠淡出
- 断点处红色脉冲光圈 2 次

---

### S3｜Reveal 作品亮相｜17–25s｜240 帧
**画面**：光带斜扫过全屏；主标题分两行弹性入场，副标与技术栈标签依次上浮。

**文案**
- Kicker：`GUARDIAN ADMIN / WEB`
- 主标题：`AI 节律守护` / `智能无感`
- 副标：`运营管理 Web 端 · 守护链条的最后一公里`
- 标签行：`Vue 3` `TypeScript` `Element Plus` `Spring Boot 3.2.5` `ECharts 6`
- 底部字幕：`让 AI 发现的每一条异常，都有人接住。`

**动效要点**
- 主标题用 `spring`（damping 16 / stiffness 90），`scale` 0.92→1
- 标题后一层错位残影（青色 + 紫色，各偏移 ±6px，透明度 0.25）
- 光带 `LightSweep` 在 17.4s 扫过

### S4｜AI 三级降级｜25–39s｜420 帧（核心）
**画面**：三张玻璃卡横向排列，代表三级 AI 链路；一条数据脉冲从左往右跑。

```
① Ollama qwen2.5:7b     ② Coze 云端智能体      ③ 规则库 12 条
   本地 · 零 API 成本        流式 SSE · 需 Token      永远可用 · 零延迟
```

**动画顺序（严格按此）**
1. 25–27s：三张卡依次弹入，卡片顶部细线亮起
2. 27–30s：脉冲从 ① 出发，① 卡片高亮 → 30s 时 ① 变灰熄灭，卡上出现 `TIMEOUT` 小标签
3. 30–33s：脉冲跳到 ②，② 高亮 → 33s 时 ② 变灰熄灭，出现 `NO TOKEN` 小标签
4. 33–36s：脉冲落到 ③，③ 亮起酸性绿，卡片放大 1.04，出现 `ALWAYS ON`
5. 36–39s：底部浮出结论条：`provider = rule` + `用户永远看不到报错`

**辅助元素**
- 右上角小徽标：`Redis CACHE · TTL 300s`
- 底部字幕（25–32s）：`本地模型跑不动？自动切云端。`
- 底部字幕（32–39s）：`云端也挂了？12 条规则兜底，回复永远不空。`

**视觉要求**：熄灭 = 去饱和 + 透明度 0.45 + 细线转灰；点亮 = 该卡颜色 glow 外发光。

### S5｜功能快切｜39–51s｜360 帧
**画面**：四张功能卡依次从右侧滑入并占满中央，每张停留 3 秒；左上角固定显示大号序号 `01/02/03/04`，右下角有网格滚动。

| 序 | 时间 | 标题 | 内容要点（取自真实实现） |
|---|---|---|---|
| 01 | 39–42s | 数据总览 | 7 个指标卡 · 近 7/14/30 天双线趋势 · ECharts 6 |
| 02 | 42–45s | 告警处置 | 按状态/级别筛选 · 填写处理说明 · 状态留痕闭环 |
| 03 | 45–48s | 用户与设备 | 手机号+验证码登录 · 角色与启停用 · 设备绑定关系 |
| 04 | 48–51s | 系统监控 | MySQL · Redis · JVM 指标 · 30 秒自动刷新 |

**动效要点**
- 卡片入场：`translateX` 120→0 + 透明度 0→1，14 帧；出场向上淡出
- 序号用 `F.mono` 超大字号（260px），透明度 0.12 作背景水印
- 每张卡片右上角一个 `Kicker` 小标签（如 `DASHBOARD` / `ALERTS` / `USERS` / `SYSTEM`）
- 底部字幕：`AI 发现 → 人来闭环 → 全程留痕`

## 四、事实核对（不得改写）

- 技术栈：Vue 3 + TypeScript + Element Plus（Web 端）、Spring Boot 3.2.5（后端）、ECharts 6.1
- AI 链路：Redis 缓存（TTL 300s）→ Ollama `qwen2.5:7b` → Coze 云端（流式 SSE）→ 本地规则库 12 条
- 规模：Web 7 页 / 8 路由；后端 67 个 Java 文件 / 17,565 行；25 个 Controller；184 个方法级接口；12 张表；小程序 36 页
- 能力边界：**不出现** RAG、Agent 工作流、Function Calling、MCP、视觉跌倒识别、ASR/TTS、微信支付、订阅消息
- 不使用"最先进""业界第一""百分百准确"等无法验证的表述
