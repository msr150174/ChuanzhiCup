# AI 功能讲解双片 · 交付说明

两支 60 秒讲解片，同一套视觉系统（深空黑底 + 霓虹青紫 + 大字报排版），复用 `theme.ts` 与共享组件，新增 `components/ai.tsx`（SectionTitle / CodeBlock / EventStream / PhoneFrame / ChatBubble / ResultBar / SceneIndex）。

## 一、成片

| 文件 | 规格 |
|---|---|
| `out/AI节律守护-后台AI-60s讲解版.mp4` | 1920×1080 / 30fps / 60.000s / 1800 帧 / H.264 / 7.52 MB / 无音轨 |
| `out/AI节律守护-小程序AI-60s讲解版.mp4` | 1920×1080 / 30fps / 60.000s / 1800 帧 / H.264 / 7.71 MB / 无音轨 |

Composition 名称：`BackendAI`、`MiniAI`（另有 `Teaser` 为第一支潮流版）。

## 二、后台 AI 片结构

| 时间 | 段落 | 画面与事实 |
|---|---|---|
| 0–6s | B1 开场 | 「后台不只是看板，是 AI 值守台」，六个能力快闪 |
| 6–22s | B2 NL2SQL | 问题「今天有多少位老人未打卡？」→ plan / sql / result / answer / done 五段事件流；SQL 逐行打出、`LIMIT 1000` 高亮；结论「今日共有 23 位老人用户未完成当日打卡（共 1 条）」；第二问「连续 3 天未打卡」→「23 位老人连续三天未打卡（共 23 条）」+ `15.7s` 计时；五道护栏 |
| 22–36s | B3 RAG | 「老人跌倒后的黄金处置时间是多少？」→ retrieval 检索 49 块命中 3 块 → 14 tokens 流式 → done；知识卡《养老护理处置规范》第 3.2 节 + 原文摘录；三个技术点 n-gram TF-IDF / 标题词加权 ×3 / 同义词扩展；未命中即说未覆盖 |
| 36–50s | B4 简报·画像·话术 | 简报 `date 2026-11-16` `checkinAbnormal 22` `medRate N/A` + 1./2./3. 建议 + `13:04:22 真实 coze 生成` `之后命中 cache`；画像 `用户0519` `healthScore 35` `riskScore 65` `较高风险` + `?limit=1` / `?limit=3`；话术 `handleNote 1~7 连续编号` `callScript 5 条` `familyScript 211 字` + 无 `---` / 括号成对 / 无「（危急）」残留 |
| 50–60s | B5 护栏与审计 | 五道护栏（只读 / 表白名单 / 禁 SELECT * / 强制 LIMIT 1000 / 5s 超时）各带一句说明 + `guardOuter()` 统一出口；`ai_call_logs` 六类 log_type；「每一步，都可核验」 |

## 三、小程序 AI 片结构

| 时间 | 段落 | 画面与事实 |
|---|---|---|
| 0–7s | M1 开场 | 「老人不会用复杂 App / 但会说话」，手机屏内首页示意 |
| 7–20s | M2 小护对话 | 「我今天睡眠怎么样？」→ 带真实健康数据的回复；右侧打卡 / 睡眠运动 / 用药三张上下文卡汇聚，标注 `AiService 组装上下文`；界面标注「界面示意」 |
| 20–34s | M3 三层降级 | Ollama TIMEOUT → Coze NO TOKEN → 规则库 ALWAYS ON；断网图标 + 降级日志 `rule hit: 心慌 → 安抚 + 紧急求助`；手机内对话继续；`provider = rule`「用户永远看不到报错」 |
| 34–46s | M4 规则库 | 12 条规则 4×3 点亮；关键词收窄对照：「健康/身体」不含「怎么样」，否则「我今天睡眠怎么样」会被抢走；适老化三标签 |
| 46–60s | M5 报告与收尾 | 睡眠评分环 78 + 一周柱状条；睡眠分析 / 日报周报 / 家属端同步；`36 页` `153 个接口` `12 张表`；「让守护，从一句话开始」 |

## 四、内容口径与边界

- 后台片全部取自 `AI能力矩阵与技术方案` 与实测记录，未新增任何未实现能力（无 Agent 工作流、无 Function Calling、无向量库、无视觉识别）。
- 小程序片按赛道二文档的真实能力写：对话、上下文注入、三层降级、12 条规则、睡眠分析与报告。**语音识别、TTS 播报、图像识别、跌倒检测未写入**（材料中为占位或待填状态）。
- 小程序侧的逐条实测记录（响应耗时、命中样本）材料里没有，片中只讲机制与两条真实对话链路，未编造数字；M2 的手机回复标注「界面示意」。
- 两支片的工程规模口径不同源：后台片用赛道一文档（184 接口 / 25 Controller / 12 表 / 17,565 行），小程序片用赛道二文档（36 页 / 153 接口 / 12 表），未混用。

## 五、重渲方式

```bash
# 后台 AI
npx remotion render BackendAI out/b1.mp4 --frames=0-899  --concurrency=6 --crf=18
npx remotion render BackendAI out/b2.mp4 --frames=900-1799 --concurrency=6 --crf=18
# out/lb.txt: file 'b1.mp4' / file 'b2.mp4'
ffmpeg -f concat -safe 0 -i lb.txt -c copy "AI节律守护-后台AI-60s讲解版.mp4"

# 小程序 AI：把 BackendAI / b1 / b2 / lb.txt 换成 MiniAI / m1 / m2 / lm.txt
```

单段渲染约 2.5 分钟（6 并发）。整片一次渲染会撞设备 20 分钟命令上限，必须分段。
