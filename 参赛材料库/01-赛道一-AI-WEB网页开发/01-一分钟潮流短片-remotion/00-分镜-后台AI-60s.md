## B1｜开场（180 帧）

- 0–30f：黑场中一条青色横线拉出，右侧计数 `06` 快速跳到 6
- 20–70f：主标 `后台不只是看板`（96px，白色），下方 `是 AI 值守台`（96px，青色）
- 60–150f：六个能力标签依次弹入，两行三列：`告警分诊` `数据问答` `知识检索` `每日简报` `风险画像` `处置话术`
- 底部字幕：`6 个 AI 能力，覆盖研判 → 问答 → 检索 → 汇总 → 预警 → 沟通`
- 150–180f：整体轻微上移淡出，接 B2

## B2｜NL2SQL 数据问答（480 帧）

版式：左侧问题 + 事件流，右侧 SQL 代码块（CodeBlock），底部结论条。

- 0–40f：SectionTitle `NL2SQL 数据问答` / 副标 `管理员不会写 SQL，也能查数`
- 30–60f：问题气泡（ChatBubble，user）：`今天有多少位老人未打卡？`
- 60–140f：事件流（EventStream）依次出现：
  - `plan` — 已通过安全校验（自动追加 LIMIT 1000 防全表拉取）
  - `sql` — 生成 SQL 完成
  - `result` — 返回 1 行
  - `answer` — 生成中文结论
  - `done` — 全链路结束
- 90–200f：右侧 CodeBlock 逐行打出：
  ```
  SELECT COUNT(*) AS cnt
  FROM users u
  LEFT JOIN checkin c
    ON c.user_id = u.id AND c.date = CURDATE()
  WHERE u.role = 'elder' AND c.id IS NULL
  LIMIT 1000;
  ```
  强调行：`LIMIT 1000`（行 5）
- 200–260f：ResultBar `answer` — `今日共有 23 位老人用户未完成当日打卡（共 1 条）`
- 260–330f：第二问出现（问题气泡）：`连续 3 天未打卡`；右侧计时徽标 `15.7s` 滚动；ResultBar `23 位老人连续三天未打卡（共 23 条）`
- 330–420f：五道护栏横向条：`只读` `表白名单` `禁 SELECT *` `强制 LIMIT 1000` `5s 超时`
- 底部字幕（分两段）：330 帧前 `SQL 由模型生成，护栏由代码兜底`；330 帧后 `越权提问在规则层就被拒绝，进不到执行环节`

## B3｜护理知识 RAG（420 帧）

- 0–40f：SectionTitle `护理知识 RAG` / 副标 `答案必须带出处，没命中就说没命中`
- 30–70f：问题气泡：`老人跌倒后的黄金处置时间是多少？`
- 70–160f：事件流：`retrieval` → 命中 3 块 → `token`（14 个 token 逐条推）→ `done`
- 100–200f：右侧知识卡片：`《养老护理处置规范》第 3.2 节` + 原文摘录 `跌倒后最初数分钟是判断伤情的关键窗口…`
- 200–300f：三个技术点竖排：`中文 n-gram TF-IDF`（离线可跑、零额度）/ `标题词加权 ×3` / `同义词扩展`（跌倒=摔倒=摔了）
- 300–360f：知识库规模条：`9,353 字` `277 行` `49 块`（单块 ≤500 字）
- 360–420f：ResultBar `无命中` — `知识库未覆盖该问题`（明确拒绝，不编造）
- 底部字幕：`不依赖向量服务，断网也能检索`

## B4｜简报 / 风险画像 / 处置话术（420 帧）

三块并排，每块 140 帧，横向滑入切换（不是叠化）。

**块 1｜每日值守简报（0–140f）**
- 标题 `每日值守简报`，Kicker `BRIEFING`
- 字段条：`date 2026-11-16` / `checkinAbnormal 22` / `medRate N/A`
- 建议列表：`1.` `2.` `3.` 连续编号
- 徽标：`13:04:22 真实 coze 生成` → `之后命中 cache`
- 底部小字：`无用药记录时 medRate 返回 N/A，不写 100%`

**块 2｜AI 风险画像（140–280f）**
- 标题 `AI 风险画像`，Kicker `RISK PROFILE`
- 大卡：`用户0519` + `healthScore 35` + `riskScore 65` + `较高风险`
- 右侧：`?limit=1` 返回 1 条 / `?limit=3` 正常返回 3 条
- 底部小字：`从"事后报警"到"事前干预"`

**块 3｜AI 处置话术（280–420f）**
- 标题 `AI 处置话术`，Kicker `COMMUNICATION`
- 三块输出：`handleNote 1~7 连续编号` / `callScript 5 条` / `familyScript 211 字`
- 质量徽标：`无 ---` `括号成对` `无「（危急）」残留`
- 底部小字：`研判结论 → 话术 → 处置记录，守护员零门槛`

## B5｜护栏 + 审计 + 收尾（300 帧）

- 0–60f：五道护栏以编号列表砸入（01–05），右侧 `guardOuter()` 代码标签
- 60–140f：审计：`ai_call_logs` + 六个 log_type 标签：`triage` `query` `rag` `briefing` `profile` `script`
- 140–200f：结论大字 `每一步，都可核验`（104px）
- 200–260f：署名：`AI 节律守护 · 智能无感`（36px 青）/ `后台 AI 值守台 · 6 个能力`（28px 灰）
- 260–300f：整体淡出
